## Method and caveats

- Each run starts from a fresh temporary data directory. The backend alone is started as the shell starts it (`--port 0 --exit-on-stdin-eof`, token in `ASSISTANT_PROF_TOKEN`); the whole app is the release shell exe, which spawns the packaged backend itself. The whole-app runs come first, so the backend-alone runs are always warm.
- "First run" is the closest this script gets to a cold start, but the OS file cache may already hold the files. A true cold start, after a reboot, is a manual check. Windows Defender also scans a new executable on its first launch, which inflates the first run after each build.
- The cold-start budget is set for a 4-core 2015-era CPU; on a faster machine, compare with care. T-806 measures on low-end hardware.
- Memory is sampled after the idle wait. Whole app = the shell process and all its descendants (WebView2 processes and the backend).
- After each whole-app run, the shell is killed (as from the Task Manager) and the backend must exit by itself within 10 s, because its stdin pipe closes (ADR-038).
- Repeated after LangGraph is added (T-402) against the ADR-029 gate.
